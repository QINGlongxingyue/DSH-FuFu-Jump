# 媒体素材转换流程

把两个原始录屏（`dt (1).mp4`、`dt (2).mp4`）转成带透明通道、边缘干净的动图。

转换脚本：`tools/mp4_to_anim.py`（不在本仓库，见下方「脚本去哪了」）。

---

## 关键参数

| 环节 | 做法 | 为什么 |
|---|---|---|
| 裁切 | ffmpeg `crop`，**只裁不缩** | 缩放交给 Pillow 的 LANCZOS，质量比 ffmpeg 好 |
| 缩放 | Pillow `LANCZOS` 降到宽 400 | ffmpeg 的 `flags=lanczos` 在暗底高对比边缘会**振铃**（halo） |
| 透明 | **亮度掩膜**：`alpha = clip((max(R,G,B) − 0.035) / (0.075 − 0.035))` | 素材是纯黑底，用亮度当 alpha 一次到位 |
| RGB | **完全不动** | 改动 RGB 会在半透明边缘渗出色偏 |
| 调色板 | GIF 全局 255 色，索引 0 作透明色 | 逐帧调色板会让透明色不稳定 |
| 输出 | `.webp`（主力）+ `.gif`（备选） | WebP 体积小一半以上且支持 8 位 alpha |

裁切框：`CROP=(600, 195, 1320, 875)`，目标宽 `TARGET_W=400`。

---

## 踩过的坑（别重犯）

1. **不要用 ffmpeg `colorkey`。**
   它是按颜色抠的，抗锯齿边缘会留下一圈**浅色白边**（因为角色边缘像素是「黑底 + 角色」的混合，
   既不是纯黑也不是角色色，抠不干净）。

2. **不要用 ffmpeg `flags=lanczos` 缩放。**
   振铃效应在暗底高对比边缘会形成一圈浅色光晕，看起来就像"瑕疵"。

3. **不要做逐像素最近色 LUT。**
   试过一次，纯 Python 循环跑了 **380 秒**，而且效果还不如亮度掩膜。

4. **裁切框底部不能留黑。**
   裁多了会在角色脚下留一条黑边；裁少一点（让底部略沉出画面）反而更自然 ——
   这也正是 `cordis.patch.yml` 里默认 `floor: 1.02` 的原因。
